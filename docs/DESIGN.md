# AI 视觉对话助手 — 设计文档

## 一、项目概述

基于多模态实时模型的 AI 视觉对话应用。用户通过浏览器打开摄像头和麦克风，AI 实时感知视频画面和用户语音，以文字+语音方式做出自然回应。

支持多模型切换（Qwen Omni / OpenAI GPT-4o / 自定义端点），覆盖六大使用场景（烹饪、寻物、学习、维修、儿童教育、无障碍辅助）。

**核心目标**：视觉理解准确、语音交互流畅、成本可控。

## 二、系统架构

```
┌─ 浏览器 (Frontend) ─────────────────────────────────────────────┐
│  三页架构: 首页 / API设置 / 对话                                 │
│                                                                  │
│  getUserMedia ──→ <video> ──→ Canvas(480p) ──→ JPEG base64      │
│       │                                                          │
│       └──→ AudioContext(16kHz) ──→ PCM16 ──→ 100ms chunk        │
│                                                                  │
│  场景系统: 6大场景卡片 → 场景化主题+角色+欢迎语                    │
│  多模型: Qwen / OpenAI / 自定义端点 + 用户自有Key                  │
│  自适应帧率: 画面静止时 0.2fps，运动时 1fps                        │
│  设备模式: 电脑端(浮动摄像头) / 手机端(全屏摄像头)                  │
│                                                                  │
│  wss://host/ws (自定义 JSON 协议，自动匹配 http/https)            │
└──────────────────────────┬───────────────────────────────────────┘
                           │
┌──────────────────────────┴───────────────────────────────────────┐
│  FastAPI Backend                                                  │
│                                                                  │
│  /ws endpoint ──→ QwenRelayClient ──→ 多模型路由                  │
│                    (双向消息中继)       ├─ Qwen DashScope          │
│                                        ├─ OpenAI Realtime         │
│                                        └─ 自定义端点               │
└──────────────────────────────────────────────────────────────────┘
```

### 数据流

1. 用户选择场景（或通用模式）、配置模型/Key（可选）
2. 浏览器采集摄像头 + 麦克风数据
3. 通过 WebSocket 发送音视频数据到后端
4. 后端中继到对应的 AI 模型 WebSocket API
5. AI 通过 server VAD 检测语音结束，生成文字+语音回复
6. 回复流式传回浏览器：文字逐字显示 + 语音缓冲播放
7. 支持语音打断、8轮自动重建 session、空闲超时保护

## 四、端云协同成本控制策略

### 已采用的策略

| # | 策略 | 方案 | 预估节省 |
|---|------|------|:---:|
| 1 | **服务端 VAD** | 开启 `server_vad`，静音时段不计费 | 50-70% |
| 2 | **降低视频分辨率** | Canvas 缩放至 854×480 (480p) | 60% |
| 3 | **JPEG 压缩** | 质量 0.6，自动降质回退（最低 0.3） | 40% |
| 4 | **自适应帧率** | 画面静止时 0.2fps，运动时 1fps | 80% |
| 5 | **默认纯文本输出** | 语音输出可关闭，仅文字回复 | 9x |
| 6 | **Token 上限** | `max_tokens: 1024` | 防失控 |
| 7 | **空闲超时** | 120 秒无活动自动断开 | 避免空转 |
| 8 | **8 轮自动重启** | 接近 8 轮限制时自动重建 session | API 要求 |
| 9 | **用户自有 Key** | 支持用户配置自己的 API Key | 100%（对项目方） |
| 10 | **多模型切换** | 支持 OpenAI 等更便宜的模型 | 灵活选择 |

### 未采用的策略及原因

| 策略 | 未采用原因 |
|------|-----------|
| 客户端 VAD | 增加复杂度，服务端 VAD 已满足需求 |
| 本地缓存常见回复 | 视觉对话内容多样，缓存命中率低 |
| WebRTC P2P 传输 | 需要信令服务器，增加部署复杂度 |
| 视频帧内容变化检测（旧版） | 已升级为自适应帧率方案（策略 4） |

## 六、WebSocket 协议设计

### 6.1 浏览器 → 后端（自定义 JSON）

```
→ { type: "start_session", model: "qwen", api_key: "...", api_url: "...", instructions: "..." }
→ { type: "audio",       data: "<base64 PCM16>" }
→ { type: "video",       data: "<base64 JPEG>" }
→ { type: "cancel" }                              // 打断
→ { type: "end_session" }

← { type: "status",      state: "listening|thinking|speaking|error" }
← { type: "text_delta",  text: "..." }
← { type: "text_done",   text: "..." }
← { type: "user_speech", text: "..." }            // 用户语音转录
← { type: "audio_delta", data: "<base64 PCM16>" }
← { type: "audio_done" }
← { type: "error",       code: "...", message: "..." }
```

### 6.2 后端 → AI 模型（原生协议）

- **Qwen DashScope**: `wss://dashscope.aliyuncs.com/api-ws/v1/realtime`
- **OpenAI Realtime**: `wss://api.openai.com/v1/realtime?model=gpt-4o-realtime-preview`
- **自定义端点**: 用户提供的任意 WebSocket URL

协议消息格式兼容 OpenAI Realtime API 规范。

## 七、音视频处理技术细节

### 采集链
```
麦克风 (48kHz Float32)
  → AudioContext({sampleRate: 16000}) 下采样
  → ScriptProcessorNode 提取 Float32Array
  → Float32 → Int16 PCM 转换
  → 100ms 缓冲 (1600 采样 = 3200 字节)
  → Int16Array → base64 编码
  → WebSocket 发送
```

### 播放链
```
WebSocket 接收 base64
  → atob 解码 → Uint8Array
  → PCM16 (2字节/采样) → Int16
  → 线性插值重采样 24kHz → AudioContext.sampleRate
  → Float32Array → AudioBuffer
  → AudioBufferSourceNode → 扬声器
```

### 视频处理
```
<video> → Canvas drawImage(0, 0, 854, 480)
  → toBlob('image/jpeg', 0.6) JPEG 编码
  → 大小检查: 若 >256KB 降质重试 (最低 0.3)
  → 自适应帧率: 像素差 < 3% → 0.2fps; > 3% → 1fps
```

## 八、部署方案

- **本地开发**: `python main.py` → `http://localhost:8000`
- **服务器部署**: `python3 main.py` + Nginx 反向代理 (HTTPS + WSS)

## 九、已知限制

1. **8 轮限制**: Qwen3-Omni-Flash 每次 session 最多 8 轮，第 7 轮自动重建
2. **120 分钟上限**: 单个 session 最长 120 分钟
3. **HTTPS 要求**: 非 localhost 环境需要 HTTPS（浏览器安全策略）
4. **ScriptProcessorNode**: 已标记废弃但广泛支持
5. **视频上下文窗口**: 240 秒滑动窗口，旧帧自动丢弃

## 十、未来增强方向

1. **AudioWorklet 迁移**: 替换 ScriptProcessorNode，降低延迟
2. **对话历史持久化**: IndexedDB 存储，离线可查看
3. **屏幕共享**: 不止摄像头，让 AI 看到电脑屏幕
4. **多语言翻译**: AI 听到中文用英文回答（或反之）
5. **手势识别**: 挥手=开始/停止，点赞=截图
6. **对话导出**: 一键导出聊天记录为图片/TXT
